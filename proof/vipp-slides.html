VIPP Search Harness · Architecture Note

You don't write the search.
You orchestrate the agent that runs it.

A harness turns the archive into skills an agent commands, and turns the team from search operators into agent orchestrators. Not a search box with an LLM bolted on, and not a workflow. It is an agent runtime whose skills happen to be retrieval.

Harness, not workflow

Who owns the control flow: the code, or the model?

The established line between two kinds of LLM system. An agentic workflow sits between them, but its control flow is still authored in code: the LLM fills the steps, it does not choose them. This harness is the third thing.

Workflow
"Systems where LLMs and tools are orchestrated through predefined code paths." The route is authored in code. Same input, same path, every time.Anthropic · Building Effective Agents
Agent
"Systems where LLMs dynamically direct their own processes and tool usage." An LLM using tools on environmental feedback, in a loop, choosing its own moves.Anthropic · Building Effective Agents
Harness
"The software infrastructure surrounding an AI model that manages everything except the model's actual reasoning." Agent = Model + Harness; the model is a pluggable part.agent-harness engineering · 2026

The tell: run the same probe twice

A pipeline has no dial for depth. A harness is nothing but that dial.

A workflow cannot vary its path, that is its whole virtue. This harness varies constantly, because the model reads what it found and decides what is next.

Workflow · fixed path
the code decides the route

identical path, every run · no dial for depth

The clean recursion

We used workflows to build the harness.

Two tools for two jobs. The harness is the right substrate for investigation; a workflow is the right tool for construction, where you want the same result every run.

Construction · a workflow
deterministic, same result every run
scaffold→ build→ gate→ adversarial review
fleets of coding agents through fixed phases
Investigation · a harness
the model finds a path you could not script
the search harness ↻
plansearchrefineverifycite
a path that cannot be known in advance
The recursion: the team practised both, orchestrating agents to build the thing that orchestrates agents.

Agent skills · the know-how layer

Two senses of "skill": what it can do, and how it knows to do it well.

MCP gives the agent tools; a skill file gives it methodology. The 6 tools are live today; the playbook layer is designed and next.

Capabilities · the tools it calls
The 6 retrieval skills, over MCP: vector, text, hybrid, transcription, multimodal search, and scene lookup. Frozen schemas, always available. What the agent can reach.
Agent Skills · the know-how it reads
Markdown playbooks: when to prefer hybrid over vector, the distinct-phrasing discipline, filter recipes, worked examples from the eval. Loaded when relevant, free until then. How the agent uses the tools well.

The skills

Six retrieval skills the agent commands over MCP.

The tools are the search-specific part; everything around them is a generic agent harness. A better model expands what these skills can do, it does not replace them.

vector_search
dense embeddings
Semantic nearest-neighbour over the embedded archive. The default probe when phrasing is loose.
text_search
lexical / BM25
Exact-term matching, for names, codes, and quoted phrases the model must not paraphrase.
hybrid_search
vector + lexical
Fuses dense and sparse signals, so a probe gets both meaning and exact matches in one call.
transcription_search
spoken content
Searches speech-to-text transcripts, to find a moment by what was said, not just shown.
multimodal_search
vision + text
Searches the frames themselves, to retrieve a scene by what it looks like.
scene_lookup
direct fetch
Resolves a known id straight to its scene and metadata, the cheap move once the target is pinned.
