The narrative

End to end, in eight steps

01–02 · setup & planning 03–08 · the autonomous loop, per ticket

  1. Boot

    npm start -- WORKFLOW.md points the engine at the target's config + agent manual.

  2. Plan

    During inception/construction, you + Claude Code write aidlc-docs/ and author Linear tickets in Todo.

  3. Poll

    The Orchestrator polls Linear for tickets in the configured active states.

  4. Isolate

    Agent Runtime creates ~/symphony-workspaces/ENG-142/, git-clones the target, writes mcp.json.

  5. Spawn

    Launches claude -p --output-format stream-json --mcp-config inside the workspace.

  6. Work

    Claude reads the ticket + repo (incl. aidlc-docs), derives the ## Workpad, implements, moves the state.

  7. Prove

    Opens a PR — CI is the proof of work — attaches it to the ticket, moves it to Human Review.

  8. Reconcile

    The State Reconciler watches Linear; the loop resumes or stops when the ticket reaches Done.

How a ticket moves

Rework is a branch off In Review: a reviewer requests changes, so the agent closes the PR, wipes the workpad, cuts a fresh branch from origin/main, and starts the loop over — a full reset, not a patch.

The one rule that anchors it all

The spec is the map; the ticket is a pin. — Design in git, execution in Linear.

The whole frame is the map — the spec, which lives in git (design: aidlc-docs/). The ticket is the smallest thing on it: a pin, tracked in Linear (execution). The worker (Claude Code) reads the map, orients by the compass (WORKFLOW.md), and traces a route (the ## Workpad) to the pin — confirming acceptance & validation landmarks. Never invert it: design in git, state in Linear.
